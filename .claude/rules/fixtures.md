# Fixture, spec and rule-artifact rules

- Every fixture directory carries a `SOURCES.md` (or the file a `_fixture` key) naming origin URL/path, licence and fetch date. EUPL-1.2 material (CEN EN 16931 examples) stays in its own attributed directory, separate from Apache-2.0 / synthetic files.
- Recorded UAPI fixtures must be masked (`mask.py` rules) before they are written; never store bearer tokens, keys, secrets, PINs or PEC passwords.
- Synthetic fixtures are marked `"_fixture": {"source": "synthetic"}` and replaced by recorded TEST responses as soon as they exist.
- `spec/` is generated by `tools/fetch_spec.py`; do not hand-edit specs or Postman files. `spec/version.txt` is the single source for `X-Api-Version`.
- `vendor/` is produced by `tools/fetch_assets.py` (`make schemas`), git-ignored, documented in `vendor/SOURCES.md`; never hand-edit.
- `frontend/public/sef/*.sef.json` is generated by `scripts/build-sef.mjs` from pinned rule-set versions; record the rule-set version in `frontend/public/sef/SOURCES.md` when refreshing.
